03 • Chris Barr (The Yahoo! Style Guide, 2010) + Scott Kubie (Writing for Designers, 2018)

Content Writing Style Guide: Information Types, Voice, Tone & Diction

Words are interface material, not post-launch decoration. Synthesizing Chris Barr & Yahoo! Editorial (eye-tracking scannability, front-loading, global plain language, UI microcopy mechanics) with Scott Kubie (Interface / Product / Marketing copy buckets, Accuracy → Clarity → Brevity editing, tone calibration, and controlled vocabularies), adopt and customize the baseline editorial rules below.

3.1 Most Common Web & UI Information Types (Kubie’s 3 Copy Buckets × Yahoo! Ch. 1 & 7)

Information Type Kubie Bucket Best-Practice Rule (Yahoo! + Kubie) Assumed Budget & Starter Pattern
1. Page Titles & Metadata Interface / Findability Make the first 65 characters count (Yahoo! Ch. 7): front-load the specific page topic before the site brand so browser tabs, bookmarks, and search results stay distinguishable. [Specific Topic] • [Brand Name] (≤ 65 chars). Never leave Untitled or generic Home.
2. Hero Value Props & Headings Marketing / Product Readers judge a page in ~3 seconds along an upper-left gaze triangle (Yahoo! Ch. 1). Use the Inverted Pyramid: lead with the conclusion and front-load concrete nouns/verbs. H1 ≤ 45 chars; section H2 ≤ 55 chars; lead summary ≤ 140 chars (1–2 crisp sentences).
3. Navigation & Text Links Interface Copy Links must make sense out of context when listed by a screen reader (Yahoo! Ch. 7). Never use bare “Click here”, “Link”, or vague “More…”; never paste raw URLs as prose link labels. Nav items: 1–2 nouns (≤ 16 chars). Inline links: verb + specific destination, e.g. “Read tournament rules”.
4. Buttons, CTAs & Prompts Interface Copy Start with an imperative action verb naming what happens next (Reserve, Download, Filter, Save). Avoid -ing gerunds and vague “Submit” / “OK” labels. 2–3 words, ≤ 24 chars, single line at 360px, e.g. [Verb] + [Object] (“Reserve Pass”).
5. Form Labels, Hints & Errors Interface Copy Keep visible <label> permanent (placeholders vanish on typing). Put format constraints above the input; write calm, non-blaming errors explaining what went wrong + how to fix it. Label ≤ 28 chars; hint ≤ 65 chars; error: DO “Enter an email with @, like name@domain.pt” vs. DON’T “Invalid input”.
6. Empty States, Modals & Receipts Interface / Product If removing the text breaks the flow, it is Interface Copy (Kubie p. 3). Confirm exact state change, item totals, reference ID, and provide one clear recovery or next-step action. State headline + 1-sentence explanation + primary recovery link/button (e.g. “No Friday sets match this filter. Reset filters.”).
7. Rules, Onboarding & FAQs Product Copy Break walls of text into 2–4 sentence paragraphs (one idea per paragraph), numbered <ol> steps for sequential tasks, and grammatically parallel <ul> bullets (Yahoo! Ch. 4 & 7). FAQ <summary> phrased as a real user question (≤ 70 chars); answer body 40–80 words in plain language.
8. Alt Text vs. Captions Product / A11y alt text substitutes for the image’s function for screen-reader and broken-image users (skip redundant “Photo of…”); <figcaption> adds visible editorial context (credits, date, place). Functional alt ≤ 110 chars; decorative flourishes require explicit empty alt="" or aria-hidden="true".

3.2 Writing Style Best Practices & Kubie’s 4-Phase Workflow

Prepare → Compose → Edit (ACB) → Finish

1. Anti-Lorem-Ipsum Workflow (Kubie Ch. 1–2)

Draft real copy before locking component dimensions: Prepare (define audience, user goal, and screen context) → Compose (write complete drafts outside tiny wireframe boxes first so premature brevity doesn’t distort meaning).

2. The ACB Editing Ladder (Kubie Ch. 3, p. 31)

Edit every string in strict sequence: Accuracy (verify facts, prices, policies—no false guarantees) → Clarity (plain words, unambiguous referents) → Brevity (cut deadwood last). Read copy aloud to expose awkward cadence.

3. Cut Deadwood & Passive Voice (Yahoo! Ch. 13)

Prefer active voice (“Your pass unlocks Vault 02”, not “Vault 02 is unlocked by…”). Strip throat-clearing fillers: replace “In order to” → “To”, “At this point in time” → “Now”, “Utilize” → “Use”.

4. Write for the World (Yahoo! Ch. 5–6)

[Specify primary language locale, e.g. EN-GB / PT-PT.] Use inclusive, bias-free, gender-neutral terms (“Crew”, “Attendees”, “They”) and avoid local slang, idioms, or sports metaphors that alienate global readers and translators.

05 • Jason Santa Maria (On Web Typography, 2014) + Modern CSS Typography

Assumed Web Typography Options, Triad Defaults & Type Scale

Following Jason Santa Maria’s On Web Typography, distinguish legibility (whether individual letterforms can be decoded) from readability (the sustained comfort and emotional clarity of reading across saccadic eye jumps). Assume the battle-tested defaults below in your style guide unless your content proves otherwise.

5.1 Typeface Evaluation & 3-Role Palette (Max 2–3 Families • Santa Maria Ch. 3–4)

Self-hosted WOFF2 • Zero faux bold/italic

1. Workhorse Body & UI (--font-body)

Assumed criteria: Tall x-height, open apertures & counters (clear a, e, c, s and I / l / 1 distinction at small sizes), moderate contrast, and real upright + true italic weights. [Swap Inter for your body workhorse.]

2. Display / “Moment” Face (--font-display)

Assumed criteria: High-personality editorial voice reserved strictly for short headlines (H1–H2, ≤ 45 chars). Pair with --font-body via deliberate structural contrast—never two nearly identical sans-serifs. [Swap Syne for your display face.]

3. Tabular Monospace (--font-mono)

Assumed criteria: Fixed-width numerals (font-variant-numeric: tabular-nums) for prices, timestamps, kickers, and code tokens so vertical columns never shift when values update. [Swap Martian Mono if needed.]

5.2 Most Common Typographic Options to Assume in Your Style Guide

Santa Maria’s Triad: Size × Measure × Leading
Default CSS typographic parameters pre-wired in @layer tokens and @layer doc-chrome
Typographic Parameter Assumed Default Option CSS Declaration Pedagogical & Optical Rationale (Santa Maria + Modern CSS)
1. Root & Body Size 1rem–1.0625rem (16–17px floor) font-size: clamp(1rem, 0.25vw + 0.92rem, 1.0625rem); Never use px or bare vw for font-size. Combining rem + vw inside clamp() honors browser root preferences and survives 200% zoom without clipping.
2. Line Length (Measure) 65ch prose (45–75ch range; 80ch max) max-inline-size: var(--measure-prose); Lines beyond 80ch cause readers to lose their place on the eye’s return sweep to the next line (Santa Maria p. 91). Use 38–45ch on mobile and captions.
3. Line Height (Leading) Unitless 1.6 body • 1.12 display line-height: 1.6; Always use unitless numbers so children scale proportionally. Tighten leading on large headlines; loosen slightly on wide measures or high-contrast dark surfaces.
4. Modular Type Scale 1.250 (Mobile) → 1.333 (Desktop) --font-size-h1 … --font-size-micro Restrained 6-step hierarchy (0.75rem micro, 0.875rem small, 1rem body, 1.3rem H3, 1.85rem H2, 2.5rem H1) prevents arbitrary one-off font sizes.
5. Alignment & Overflow Logical ragged-end (start) text-align: start; overflow-wrap: break-word; Avoids ugly rivers of whitespace caused by text-align: justify (if justification is ever required, pair with hyphens: auto) and prevents long URLs from breaking mobile layouts.
6. Modern Text Wrapping balance heads • pretty prose h1, h2, h3 { text-wrap: balance; } p { text-wrap: pretty; } Eliminates orphaned 1-word last lines. Gotcha: never put balance/pretty on *, and avoid text-wrap: balance on bordered/filled boxes (buttons, pills) where it leaves awkward trailing space inside the box.
7. Tracking, Case & Emphasis -0.02em display • 0 body • +0.08em kickers letter-spacing: -0.02em; Word coastline shapes live in lowercase ascenders/descenders (Santa Maria Ch. 1): avoid multi-word ALL-CAPS blocks; use semantic <strong>/<em> sparingly rather than bolding whole paragraphs.
8. Figures & Punctuation Curly quotes “ ” ’ • – / — • tabular-nums font-variant-numeric: tabular-nums; Use real typographic quotes/apostrophes, en-dashes (–) for time/date ranges, em-dashes (—) for clause breaks, and modular margin-block-end rhythm instead of fragile print baseline grids (Santa Maria p. 118).
