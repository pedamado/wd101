1. A Regra de Ouro do Ponto de Partida: 1rem = 16px 1. The Golden Baseline Rule: 1rem = 16px

Por omissão em todos os navegadores contemporâneos, a folha de estilo interna (User-Agent Stylesheet) define para o elemento raiz :root { font-size: 16px; }. Esta medida não é arbitrária: decorre de décadas de ergonomia de leitura em monitores padrão a uma distância de visualização de 50 a 70 centímetros. By default across all contemporary browsers, the user-agent stylesheet sets root :root { font-size: 16px; }. This measurement is not arbitrary: it stems from decades of reading ergonomics on desktop monitors viewed from a 50–70 cm distance.

⚠️ O Anti-Padrão da Trapacearia dos 62.5%The 62.5% Trick Anti-Pattern
Durante anos, muitos tutoriais sugeriram declarar html { font-size: 62.5%; } para forçar 1rem = 10px (facilitando as contas de cabeça). For years, legacy tutorials promoted declaring html { font-size: 62.5%; } to force 1rem = 10px for easier mental math.

Isto é uma violação grave de Acessibilidade (WCAG 2.2):This is a severe Accessibility violation (WCAG 2.2): Se um utilizador com baixa visão configurar o seu browser para ter 24px de texto base por necessidade oftalmológica, o cálculo forçado de 62.5% esmaga e desrespeita essa preferência vital do utilizador! If a user with low vision configures their browser base font to 24px for optical accommodation, the forced 62.5% scaling crushes and disregards that vital preference!

A Boa Prática:Best Practice: Deixe o elemento html intacto ou use font-size: 100%. Desenhe a hierarquia aceitando 1rem = 16px como o padrão natural e utilize unidades relativas para todo o dimensionamento. Leave the html element untouched or set font-size: 100%. Design typography accepting 1rem = 16px as the natural baseline and use relative units throughout.

2. Estratégias de Distribuição: CDNs Hospedadas vs. Auto-Hospedagem (Vendorização) 2. Distribution Strategies: Hosted CDNs vs. Self-Hosting (Vendorization)

Na passagem do EX2 (onde recorremos à ligação remota via Google Fonts) para o Projeto Capstone Drumtiks, migramos para a auto-hospedagem (self-hosting / vendorized). Compreender as diferenças e compromissos é essencial para a autonomia profissional do designer. In transitioning from EX2 (remote webfonts via Google Fonts) to the Drumtiks Capstone Project, we migrate to self-hosting (vendorized WOFF2). Understanding the architectural tradeoffs is essential for professional designer autonomy.

Otimizações Críticas em @font-face: WOFF2, font-display e unicode-range

O formato WOFF2 utiliza o algoritmo de compressão Brotli, sendo 30% a 50% mais leve que o WOFF clássico. A declaração font-display: swap garante que o texto é imediatamente renderizado com uma fonte de sistema, sendo substituído assim que o ficheiro WOFF2 estiver pronto (evitando texto invisível / FOIT).

/* Exemplo extraído do fonts.css do Festival Drumtiks '26 */ @font-face { font-family: 'Syne'; font-style: normal; font-weight: 400 800; /* Eixo contínuo de pesos 400 a 800 */ font-display: swap; /* Elimina o FOIT (Flash of Invisible Text) */ src: url('../assets/fonts/Syne-latin-var.woff2') format('woff2'); unicode-range: U+0000-00FF, U+0131, U+0152-0153; /* Apenas carateres necessários */ }

3. Fontes Variáveis: Eixos Canónicos vs. Eixos Customizados 3. Variable Fonts: Registered Axes vs. Custom Axes

Enquanto a tipografia web clássica exigia carregar 8 ou 12 ficheiros estáticos separados (Regular, Medium, Bold, Italic, etc.), uma Fonte Variável (Variable Font) compacta toda essa família tipográfica num único ficheiro dinâmico com eixos de interpolação contínuos. While classic web typography required downloading 8 to 12 separate static font files, a Variable Font bundles an entire design family into a single compact file with continuous interpolation axes.

A Regra de Ouro: Propriedades de Alto Nível vs. font-variation-settings Sempre que possível, utilize as propriedades padrão de alto nível do CSS:
  • font-weight: 560; (controla o eixo padrão wght)
  • font-stretch: 85%; (controla o eixo padrão wdth)
  • font-style: oblique 12deg; (controla o eixo padrão slnt)
Adenda Importante: Eixos Customizados
Algumas fontes variáveis contêm eixos proprietários desenhados pelo autor (como 'CASL' para casualidade, 'CRSV' para cursividade ou 'GRAD' para compensação ótica de peso sem reflow). **Esses eixos customizados têm obrigatoriamente de ser manipulados através de font-variation-settings:**
/* Eixos customizados de 4 letras exigem font-variation-settings */ h1.branded-title { font-variation-settings: 'GRAD' 150, 'CASL' 0.75; }

4. O Emparelhamento Tipográfico: A Tríade do Festival Drumtiks 4. Typographic Pairing: The Drumtiks Festival Triad

Para websites com densidade editorial e riqueza visual, a abordagem recomendada no curso é a Tríade Tipográfica Funcional: três famílias especializadas que desempenham papéis semânticos e espaciais claros: For editorial density and expressive web experiences, the recommended course model is the Functional Typographic Triad: three distinct families with explicit structural roles:

1. FONTE DE MARCA / DISPLAY

Syne Variable

Geométrica, expressiva e angular. Utilizada exclusivamente em títulos monumentais (h1, h2), logótipo e cartazes do festival. Não deve ser usada em texto corrido devido às suas formas expressivas que cansam o leitor em blocos longos.

2. FONTE DE CORPO / EDITORIAL

Inter Variable

Desenhada especificamente para ecrãs digitais. Apresenta altura-x (*x-height*) generosa, aberturas amplas e contraste neutro. Utilizada em parágrafos de leitura, biografias, FAQs e menus.

3. FONTE TÉCNICA / METADADOS

Martian Mono

Monoespaçada de inspiração industrial brutalista. Utilizada para horários, timecodes de BPM, preços de bilheteira, badges de estado e blocos de código, transmitindo precisão analógica.

5. Escalas Modulares & Progressão Pedagógica em Dois Momentos 5. Modular Scales & Two-Stage Pedagogical Progression

Em vez de escolher tamanhos de letra ao acaso (ex: 18px, 23px, 37px), uma Escala Modular Tipográfica aplica uma razão geométrica musical para que todos os tamanhos da hierarquia sejam harmónicos entre si. Rather than picking arbitrary font sizes, a Modular Typographic Scale applies a musical geometric ratio ensuring proportional harmony across every heading and body level.

A razão recomendada como base nos exercícios da FBAUP é a **Major Third (1.250)**. No entanto, incentivamos os estudantes a explorar outros rácios matemáticos em ferramentas como o TypeScale.com ↗:

  • Minor Third (1.200): Ideal para dashboards e interfaces densas com espaço reduzido.
  • Major Third (1.250 — Recomendada): Equilibrada, elegante e versátil para websites de conteúdo.
  • Perfect Fourth (1.333): Maior contraste dramático entre títulos e corpo de texto.
  • Golden Ratio (1.618): Monumental e dramática, perfeita para cartazes e pósteres.

A Abordagem Pedagógica em Dois Momentos Curriculares:

MOMENTO 1: INICIAL / FUNDACIONAL

Trabalhamos com os valores **explicitamente calculados em unidades rem** aplicados diretamente nos seletores:

body { font-size: 1rem; } /* 16.00px (Base) */ h3 { font-size: 1.25rem; } /* 20.00px (16 * 1.25) */ h2 { font-size: 1.563rem; } /* 25.00px (20 * 1.25) */ h1 { font-size: 1.953rem; } /* 31.25px (25 * 1.25) */
MOMENTO 2: AVANÇADO (2.ª METADE DO SEMESTRE)

Migramos para a **Tokenização do Design System**, armazenando os passos da escala em Variáveis CSS em :root:

:root { --scale-ratio: 1.25; --step-0: 1rem; --step-1: calc(var(--step-0) * var(--scale-ratio)); --step-2: calc(var(--step-1) * var(--scale-ratio)); --step-3: calc(var(--step-2) * var(--scale-ratio)); }

6. Tipografia Fluida com clamp() (Sem Media Queries)

Tradicionalmente, os designers criavam degraus rígidos com dezenas de @media (min-width: ...). Se o ecrã encolhesse 1 pixel, o título sofria um solavanco abrupto. Com a função matemática nativa clamp(), o tamanho da fonte escala de forma perfeitamente suave e linear entre uma largura mínima e máxima da janela de visualização.

/* Sintaxe Canónica do clamp() */ font-size: clamp(mínimo, valor-preferido-fluido, máximo); /* Exemplo prático do Festival Drumtiks '26 */ .hero-title { font-size: clamp(2.25rem, 5.5vw + 1rem, 4.5rem); }
Acessibilidade Crítica: Porquê somar vw com rem? Se declarar apenas font-size: clamp(2rem, 8vw, 5rem);, a unidade vw pura ignora a configuração de zoom de acessibilidade do browser!

Ao adicionar uma base em rem no valor central (ex: 5.5vw + 1rem), garantimos que quando o utilizador ativa a ampliação de texto do navegador, a componente rem continua a expandir o texto, cumprindo o **Critério 1.4.4 da WCAG (Resize Text)**.

🔭 O Futuro Imediato: Tipografia Relativa ao Contentor com unidades cqi

Enquanto o vw escala com a largura total da janela, as Container Queries permitem calcular a tipografia fluida com base no espaço do contentor pai através da unidade cqi (*Container Query Inline*). Isso permite que o mesmo cartão de festival adapte a sua tipografia quer seja inserido numa barra lateral estreita (320px) ou na área principal (800px) sem qualquer media query!

.album-card { container-type: inline-size; } .album-card-title { font-size: clamp(1.15rem, 2cqi + 0.6rem, 1.85rem); }

7. Ergonomia de Leitura: Comprimento de Linha (Measure) & Entrelinha (Leading)

A Medida Ideal: 45 a 75 carateres (ch)

Linhas excessivamente longas cansam o olho na procura do início da linha seguinte; linhas demasiado curtas quebram o ritmo sintático. A unidade ch representa a largura do zero (0) da fonte ativa:

p, .bio-text { max-width: 65ch; /* Zona ergonómica de conforto */ }

A Relação Inversa de Entrelinha (line-height)

Quanto maior o tamanho do tipo, mais apertada deve ser a entrelinha para manter as palavras ligadas; em texto corrido pequeno, a entrelinha deve ser mais aberta:

/* Títulos monumentais */ h1 { line-height: 1.1; } /* Texto de leitura (corpo) */ p { line-height: 1.55; } /* SEMPRE sem unidades! */

8. Micro-Tipografia: Quebras Inteligentes, Hifenação & Sublinhados

As adições mais recentes ao CSS Living Standard fornecem controlo tipográfico fino sem necessidade de scripts externos:

Propriedade CSS Função & Comportamento Exemplo Recomendado
text-wrap: balance; Equilibra o número de carateres por linha em títulos e cabeçalhos curtos, eliminando palavras solitárias no final. h1, h2, h3, blockquote { text-wrap: balance; }
text-wrap: pretty; Algoritmo otimizado para blocos de texto corrido; impede que a última linha de um parágrafo termine com uma única palavra órfã. p, li, figcaption { text-wrap: pretty; }
hyphens: auto; Hifenação automática inteligente. Exige que o atributo de idioma esteja correto no HTML (ex: <html lang="pt">). article p { hyphens: auto; }
text-underline-offset Afasta a linha de sublinhado da linha de base tipográfica, melhorando a legibilidade e estética dos hiperlinks. a { text-underline-offset: 0.25em; }
text-decoration-skip-ink Interrompe o traço de sublinhado quando este cruza as hastes descendentes de letras como 'p', 'q', 'g' ou 'y'. a { text-decoration-skip-ink: auto; }

9. Semântica Inline & Diferenciação Visual Expressiva

A web não é feita apenas de parágrafos planos. A formatação de texto deve refletir o significado semântico exato, sendo visualmente enriquecida pelas fontes versáteis:

  • <strong>: Importância séria ou urgência (renderizada com peso 800 na Inter). Diferente de <b> que é meramente estilístico.
  • <em>: Ênfase verbal que altera o tom de leitura (renderizada em itálico real com eixo ital 1).
  • <abbr title="...">: Abreviações e siglas técnicas (ex: MVC, BPM) com cursor help acessível.
  • <del> e <ins>: Representam texto removido e texto inserido em revisões (ex: Bilhetes 45.00 € 35.00 €).
  • <mark>: Realce de relevância contextual (ex: termos de pesquisa encontrados no programa).
  • <code>, <kbd>, <samp>: Fragmentos de código, teclas premidas pelo utilizador (Cmd + S) e mensagens do terminal renderizadas com a Martian Mono.
  • <blockquote> e <q>: Citações em bloco com aspas inteligentes automáticas e <cite> para referenciar a fonte bibliográfica.
  • <sup> e <sub>: Expoentes matemáticos e notas de rodapé (ex: 1.ª edição, $E = mc^2$).
