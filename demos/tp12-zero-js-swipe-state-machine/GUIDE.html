Fundamento 01 O Paradigma Zero-JS: Reatividade sem Camadas de Script The Zero-JS Paradigm: Reactivity Without Script Layers

No currículo do Web Design 101 da FBAUP, o conceito de Zero-JS State Machine (Máquina de Estados Zero-JavaScript) não é um mero capricho purista: é o teste supremo do domínio da árvore DOM, da semântica de formulários e das regras de cascata e especificidade do CSS moderno.

Ao transferir a gestão de estados interativos (como páginas ativas, menus abertos ou modos de visualização) para o motor nativo em C++ do navegador, os designers alcançam:

  • Fiabilidade Absoluta (Zero Runtime Errors): Um script pode falhar por bloqueios de rede, extensões ad-blocker ou exceções de parsing; o CSS é imune a crashes de execução.
  • Aceleração por Hardware GPU: As transições acionadas por propriedades compostas (transform e opacity) correm na camada do Compositor do motor gráfico, mantendo 60 a 120 FPS cravados em ecrãs ProMotion de smartphones.
  • Acessibilidade Nativa: Ao utilizar elementos nativos de formulário como <input type="radio">, o estado é exposto instantaneamente a tecnologias de apoio (leitores de ecrã) sem exigir scripts ARIA manuais.

Fundamento 02 Geometria do Contentor: Viewport 100dvh & Blindagem Anti-Horizontal Scroll Container Geometry: 100dvh Viewport & Anti-Horizontal Scroll Containment

Um dos erros mais comuns de iniciantes no desenvolvimento móvel é a criação de barras de deslocamento laterais involuntárias ao fazer deslizar cartões horizontalmente. O demonstrador resolve este problema com uma arquitetura em 3 camadas estanques:

┌────────────────────────────────────────────────────────────────────────┐ │ WINDOW / VIEWPORT (100dvw x 100dvh) — overflow: hidden │ │ │ │ ┌──────────────────────────────────────────────────────────────────┐ │ │ │ #wrapper.app-wrapper (width: 100vw; max-width: 100%; 100dvh) │ │ │ │ │ │ │ │ ┌─────────────────── .slider-track (400% width) ─────────────┐ │ │ │ │ │ [Article 1 (100%)] [Article 2 (100%)] [Article 3] [Art. 4] │ │ │ │ │ └────────────────────────────────────────────────────────────┘ │ │ │ │ │ │ │ │ ←─── Deslocamento com translateX(calc(...)) na GPU ─────────→ │ │ │ └──────────────────────────────────────────────────────────────────┘ │ └────────────────────────────────────────────────────────────────────────┘

Porquê a Unidade 100dvh em vez de 100vh?

A unidade tradicional vh baseia-se na altura teórica máxima da janela. No entanto, em navegadores móveis como o Safari (iOS) ou o Chrome (Android), a barra de endereços retrai-se quando o utilizador faz scroll e expande-se quando para. Isso causava saltos visuais e botões de rodapé cortados.

A moderna especificação CSS Values and Units Level 4 introduziu:

  • svh (Small Viewport Height): Altura quando as barras do browser estão totalmente visíveis.
  • lvh (Large Viewport Height): Altura quando as barras do browser estão recolhidas.
  • dvh (Dynamic Viewport Height): Altura dinâmica viva que se recalcula suavemente à medida que a interface do sistema operativo se transforma!
/* Blindagem no contentor principal contra scrolls indesejados */ #wrapper.app-wrapper { position: relative; width: 100vw; max-width: 100%; height: 100dvh; min-height: 100dvh; overflow: hidden; /* Corta estritamente qualquer transbordo horizontal */ display: flex; flex-direction: column; }

Técnicas em Detalhe Comparação das Três Técnicas de Deslocamento Comparative Analysis of the Three Motion Techniques

Técnica 1: Deslocamento Matricial com calc()

Nesta técnica, a faixa inteira (.slider-track) move-se ao longo do eixo X com uma única fórmula matemática parametrizada por uma variável CSS:

/* O ancestral deteta qual o input radio selecionado e define a variável de índice */ #wrapper:has(#round-1:checked) { --active-index: 0; } #wrapper:has(#round-2:checked) { --active-index: 1; } #wrapper:has(#round-3:checked) { --active-index: 2; } #wrapper:has(#round-4:checked) { --active-index: 3; } /* A fita desliza multiplicando o índice por -100% da largura do contentor */ .slider-track { transform: translate3d(calc(var(--active-index) * -100%), 0, 0); transition: transform 0.65s cubic-bezier(0.16, 1, 0.3, 1); }

Vantagem pedagógica: Elimina código repetitivo. Para adicionar um 5.º ou 6.º round de batalha, basta associar o novo ID do radio ao seu respetivo inteiro no seletor :has().

Técnica 2: Direcionamento por Atributos HTML data-*

O HTML declara explicitamente o destino de cada secção em atributos semânticos, como data-page="0" ou data-offset="-100%". O CSS utiliza Seletores de Atributos para mapear e aplicar as translações.

<!-- Estrutura declarada no HTML --> <article class="battle-stage" data-page="1" data-offset="-100%">...</article> /* CSS mapeado diretamente pelo seletor de atributo */ #wrapper:has(#mode-data:checked):has(#round-2:checked) .slider-track { transform: translate3d(-100%, 0, 0); }

Fronteira Futura (CSS Values Level 5): A especificação futura permitirá extrair números de atributos diretamente com tipos: calc(attr(data-page type(<integer>)) * -100%).

Técnica 3: Iterador Moderno CSS (sibling-index() & Contagem de Irmãos)

O mais recente patamar da especificação W3C CSS Values and Units Module Level 5 § 10.3 introduz a função nativa sibling-index(), que devolve o índice 1-based do elemento entre os seus irmãos, eliminando a necessidade de escrever classes de contagem!

/* Padrão com a função nativa sibling-index() */ @supports (transform: translateX(calc(sibling-index() * 100%))) { .battle-stage { transform: translate3d(calc(((sibling-index() - 1) - var(--active-index)) * 100%), 0, 0); } } /* Fallback de Produção: Contagem via :nth-child() */ .battle-stage:nth-child(1) { --sibling-index: 1; } .battle-stage:nth-child(2) { --sibling-index: 2; } .battle-stage:nth-child(3) { --sibling-index: 3; } .battle-stage:nth-child(4) { --sibling-index: 4; }

Variante 4 Modo Furtivo de Produção: Inputs Ocultos & Zonas Táteis de Swipe Production Stealth Mode: Invisible Inputs & Touch Swipe Hit-Areas

Numa aplicação web real destinada a smartphones, os botões circulares nativos de rádio não devem estar visíveis. No entanto, NUNCA se deve usar display: none ou visibility: hidden nos inputs, pois isso desativa a focagem por teclado (Tab) e remove os controlos da árvore de acessibilidade para tecnologias de apoio.

Padrão de Ocultação Acessível (Visually Hidden):

/* Esconde visualmente mas mantém no Accessibility Tree do sistema operativo */ .visually-hidden:where(:not(:focus-within, :active)) { position: absolute !important; clip-path: inset(50%) !important; overflow: hidden !important; width: 1px !important; height: 1px !important; margin: -1px !important; border: 0 !important; }

Simulação de Click-to-Swipe por Camadas Táteis Transparentes:

Em cada <article>, inserimos dois elementos <label> transparentes que cobrem as margens esquerda e direita do ecrã (15% da largura cada):

  • Margem Esquerda: <label for="round-1" class="swipe-hit-area swipe-prev"> — Clicar nesta área comuta para o round anterior!
  • Margem Direita: <label for="round-3" class="swipe-hit-area swipe-next"> — Clicar nesta área comuta para o round seguinte!

Esta arquitetura permite ao utilizador tocar em qualquer ponto das margens do ecrã no telemóvel para avançar ou recuar os slides, exatamente como numa aplicação nativa de histórias ou carrossel swipe!

Engenharia CSS Matriz de Especificidade & Referências Oficiais MDN Specificity Matrix & Official MDN References

A especificidade em CSS é calculada na tripla formal (A, B, C):

  • A: Seletores de ID (ex: #wrapper, #round-1).
  • B: Classes (.slider-track), Atributos ([data-page]) e Pseudo-classes (:has(), :checked).
  • C: Elementos HTML (article, header, main).

Glossário Completo de Combinadores Utilizados:

  • Combinador Descendente (espaço em branco): #wrapper .slider-track — Seleciona qualquer descendente em qualquer nível de profundidade. [MDN]
  • Combinador Filho Direto (>): .slider-track > article — Seleciona exclusivamente filhos imediatos de 1.º nível. [MDN]
  • Combinador de Irmão Adjacente (+): input:checked + label — Seleciona o irmão imediatamente seguinte. [MDN]
