04 • Container Queries: Fast & Modular Layouts

Traditional @media queries force you to re-architect all selectors across the whole site based on the viewport width. With CSS Container Queries (@container), a component adapts intrinsically based strictly on the width of its immediate parent container (container-type: inline-size). The same component works identically in a 320px sidebar, a 540px grid column, or a 920px hero banner without writing a single viewport query!

CSS View • Active Container Query Engine Rules Pure Layout CSS 
/* ==========================================================================
   1. DECLARE THE CONTAINER CONTEXT
   ========================================================================== */
.query-container {
  /* Allows descendants to query this container's horizontal inline size */
  container-type: inline-size;
  container-name: disc-slot;      /* Optional named container */
  width: 100%;
}

/* ==========================================================================
   2. DEFAULT / NARROW LAYOUT (< 440px)
   Applied when inside a narrow slot (e.g. mobile screen or sidebar).
   1D Flexbox Vertical Stack.
   ========================================================================== */
.adaptive-disc-card {
  display: flex;
  flex-direction: column;         /* Stack artwork and details vertically */
  gap: 1rem;
}

/* Fluid Typography using Container Query Units (cqi = 1% of container inline width) */
.disc-card-title {
  font-size: clamp(1.15rem, 2cqi + 0.6rem, 1.85rem);
}

.disc-extended-tracklist {
  display: none;                  /* Hidden in tight containers */
}

/* ==========================================================================
   3. MEDIUM CONTAINER BREAKPOINT (>= 440px)
   Triggers when the PARENT CONTAINER reaches 440px!
   1D Flexbox Horizontal Row.
   ========================================================================== */
@container disc-slot (min-width: 440px) {
  .adaptive-disc-card {
    flex-direction: row;          /* Horizontal side-by-side flow */
    align-items: center;
    gap: 1.5rem;
  }

  .disc-art-wrapper {
    width: 150px;
    height: 150px;
  }
}

/* ==========================================================================
   4. WIDE CONTAINER BREAKPOINT (>= 740px)
   Triggers when the PARENT CONTAINER reaches 740px!
   Switches internally to a 2D CSS Grid Matrix with rich multi-column data!
   ========================================================================== */
@container disc-slot (min-width: 740px) {
  .adaptive-disc-card {
    display: grid;
    grid-template-columns: 200px 1fr 240px; /* 3-column panoramic grid */
    align-items: center;
    gap: 2rem;
  }

  .disc-art-wrapper {
    width: 200px;
    height: 200px;
  }

  .disc-extended-tracklist {
    display: flex;                /* Reveal extended tracks in wide containers */
  }
}
Pedagogical Cheat Sheet

Barebone Structural Blueprint: Container Queries

Summary of Structural Requirements: Container queries decouple responsive component design from the global viewport. Instead of coordinating complex, fragile @media queries across the entire page, you simply declare container-type: inline-size on any parent element. Inside, the component uses @container (min-width: ...) to transition seamlessly between 1D Flexbox (vertical stack or horizontal row) and 2D CSS Grid. Below is the minimal structural blueprint with zero visual styling details.

1. Barebone HTML5 Landmarks HTML 
<!-- Landmark: Main Content -->
<main>

  <!-- Parent Query Container (Declares container-type) -->
  <div class="query-container">

    <!-- Adaptive Child Component -->
    <article class="adaptive-card">
      <div class="card-media">Media/Art</div>

      <div class="card-content">
        <h3>Item Title</h3>
        <p>Item Description...</p>
        <div class="card-extra">Extra Info</div>
      </div>
    </article>

  </div>

</main>
2. Core Structural Selectors & Properties CSS (Zero Visual Fluff) 
/* 1. CONTAINER LEVEL (Enables Container Queries) */
.query-container {
  container-type: inline-size;    /* Queries horizontal width */
  container-name: card-slot;      /* Optional named reference */
  width: 100%;
}

/* 2. BASE COMPONENT (Narrow / Mobile: 1D Flex Stack) */
.adaptive-card {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

.card-extra {
  display: none;                  /* Hidden in tight containers */
}

/* 3. CONTAINER BREAKPOINT 1 (Medium: 1D Flex Row) */
@container card-slot (min-width: 440px) {
  .adaptive-card {
    flex-direction: row;          /* Horizontal side-by-side */
    align-items: center;
  }
}

/* 4. CONTAINER BREAKPOINT 2 (Wide: 2D CSS Grid Matrix) */
@container card-slot (min-width: 740px) {
  .adaptive-card {
    display: grid;
    grid-template-columns: 200px 1fr auto;
    align-items: center;
  }

  .card-extra {
    display: block;               /* Reveal in wide spaces */
  }
}

Pedagogical Anatomy: Why Container Queries Win Over @media

1. The Viewport Query Flaw

Traditional @media (min-width: 768px) only measures the browser window. If you place a card inside a narrow 300px sidebar on a 1920px screen, @media thinks you have plenty of room and breaks the layout!

2. container-type: inline-size

Declaring container-type: inline-size instructs the browser to monitor the width of the containing element. The child component queries its own allocated real estate, rendering identically anywhere in the application.

3. Container Query Units (cqi)

Just as vw represents 1% of the viewport, 1cqi represents 1% of the container's inline width. With font-size: clamp(1rem, 2cqi, 1.8rem), typography scales with component size, not screen size.

4. Zero Modifier Classes

You no longer need brittle BEM modifier classes like .card--sidebar or .card--hero. The component detects its parent's geometry and morphs autonomously between Flexbox and CSS Grid!
