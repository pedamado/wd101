CSS View • Active Flexbox Engine Rules Pure Layout CSS 
/* ==========================================================================
   1. FLEX CONTAINER RULES (.tracklist-flex-board)
   ========================================================================== */

/* Mobile First (Single Column Stack) */
.tracklist-flex-board {
  display: flex;                  /* Initializes the flex formatting context */
  flex-direction: column;         /* Main axis runs top-to-bottom */
  flex-wrap: nowrap;              /* All items stack vertically on mobile */
  gap: 1.25rem;                   /* Modern gutter spacing between all flex items */
  width: 100%;
}

/* Desktop Breakpoint: Multi-Row Wrapping Card Layout */
@media (min-width: 768px) {
  .tracklist-flex-board {
    flex-direction: row;          /* Main axis switches to horizontal (left-to-right) */
    flex-wrap: wrap;              /* Items break onto new lines when row fills */
    justify-content: flex-start;  /* Pack items toward start of main axis */
    align-items: stretch;         /* Cross-axis: stretch items to match tallest in row */
  }
}

/* ==========================================================================
   2. FLEX ITEM SIZING & RATIOS (.track-card)
   ========================================================================== */
.track-card {
  /*
    Shorthand: flex:   
    - flex-grow: 1   (expands to fill leftover empty space on its row)
    - flex-shrink: 1 (shrinks proportionally if viewport is constrained)
    - flex-basis: 320px (ideal starting size on desktop before wrapping)
  */
  flex: 1 1 320px;
  min-width: 280px;               /* Safety floor: prevents item collapsing below legibility */

  /* Internal Card Alignment (Item is also a Flex Container!) */
  display: flex;
  flex-direction: column;
  justify-content: space-between; /* Pushes technique bio and footer to opposite ends */
  gap: 1rem;
}

/* Wide Variation: Forces earlier wrap */
.track-card.card-wide {
  flex-basis: 460px;
}

/* Compact Variation: Fits in tighter rows */
.track-card.card-compact {
  flex-basis: 260px;
}

/* Internal Flex Stretcher */
.track-technique-bio {
  flex-grow: 1;                   /* Absorbs internal vertical space */
}

/* Spatial Pinning via Auto-Margin */
.tag-duration {
  margin-left: auto;              /* Consumes all remaining row space; pins to far right! */
}

/* ==========================================================================
   3. VISUAL REORDERING (order property)
   ========================================================================== */
/* Move pinned/featured track to the first position */
.track-card.card-featured {
  order: -10;                     /* Negative order renders BEFORE natural order: 0 */
}
Pedagogical Cheat Sheet

Barebone Structural Blueprint: Pure Flexbox

Summary of Structural Requirements: Flexbox is a 1-dimensional layout tool. To build a responsive card layout that transitions from a single mobile column to a desktop wrapping grid, only two structural components are strictly required: (1) a Flex Container establishing the main axis and wrapping rules, and (2) Flex Items with proportional sizing (flex-grow, flex-shrink, flex-basis). No decorative styling (colors, fonts, borders, shadows) is needed for the layout logic to work.

1. Barebone HTML5 Landmarks HTML 
<!-- Landmark: Main Content -->
<main>

  <!-- Landmark: Section acting as Flex Container -->
  <section class="flex-container">

    <!-- Landmark: Article acting as Flex Item -->
    <article class="flex-item flex-wide">
      <h3>Item 1</h3>
      <p>Item content...</p>
      <span class="pin-right">End</span>
    </article>

    <article class="flex-item">
      <h3>Item 2</h3>
      <p>Item content...</p>
      <span class="pin-right">End</span>
    </article>

    <article class="flex-item flex-pinned">
      <h3>Item 3 (Pinned)</h3>
      <p>Item content...</p>
      <span class="pin-right">End</span>
    </article>

  </section>

</main>
2. Core Structural Selectors & Properties CSS (Zero Visual Fluff) 
/* 1. CONTAINER LEVEL (Axes, Flow & Distribution) */
.flex-container {
  display: flex;                  /* Activates 1D flex context */
  flex-direction: column;         /* Mobile: single column stack */
  gap: 1.5rem;                    /* Gutters between items */
}

@media (min-width: 768px) {
  .flex-container {
    flex-direction: row;          /* Desktop: horizontal flow */
    flex-wrap: wrap;              /* Wraps onto multiple rows */
    justify-content: flex-start;  /* Main axis alignment */
    align-items: stretch;         /* Cross axis: equal heights */
  }
}

/* 2. ITEM LEVEL (Sizing Ratios & Positioning) */
.flex-item {
  flex: 1 1 300px;                /* grow: 1, shrink: 1, basis: 300px */
  min-width: 250px;               /* Safety width limit */
  display: flex;                  /* Nested flex for internal push */
  flex-direction: column;
}

.flex-wide {
  flex-basis: 450px;              /* Wider basis = wraps earlier */
}

.flex-pinned {
  order: -1;                      /* Visually moved to first slot */
}

.pin-right {
  margin-left: auto;              /* Consumes space; pushes to right */
}

Pedagogical Anatomy: The CSS Flexbox Engine

1. Main Axis vs. Cross Axis

Unlike standard Block/Inline flow or CSS Grid, Flexbox operates along one axis at a time. When flex-direction: row is active, the Main Axis runs horizontally (left to right in LTR), and the Cross Axis runs vertically. When set to column, the axes flip: the Main Axis runs top-to-bottom.

2. flex: grow shrink basis

The flex: 1 1 320px shorthand defines:
• flex-grow (1): How much extra space the card absorbs.
• flex-shrink (1): Rate at which the card shrinks if space is tight.
• flex-basis (320px): The ideal starting size before distribution.

3. The Magical Auto-Margin

In Flexbox, margin-left: auto or margin-inline-start: auto consumes all available leftover space along the main axis, pushing elements like our track duration (.tag-duration) cleanly to the opposing edge without requiring float or absolute positioning!

4. The order Property & A11y Caveat

The order property alters visual rendering order only. The DOM source order and keyboard TAB navigation order remain strictly unchanged. Never use order to replace logical HTML markup sequence for screen readers!
