1. Manifesto Pedagógico: A Armadilha do Assistente & A "Carta de Condução" 1. Pedagogical Manifesto: The Assistant Trap & The "Driver's License"

Na aprendizagem de Web Design e Design de Comunicação, a inteligência artificial generativa sem restrições é perigosa: ela sofre do "Viés do Assistente Prestável". Ao fornecer de imediato blocos de código prontos a colar, o modelo rouba ao estudante o esforço produtivo (productive struggle), criando a ilusão de competência. O estudante cola o código, o layout funciona no momento, mas na primeira avaria ou necessidade de ajuste visual fino, fica completamente indefeso. In communication and web design education, unrestricted generative AI carries a severe pedagogical risk: the "Helpful Assistant Bias". By immediately providing turnkey code snippets, standard LLMs rob the student of the productive struggle, generating an illusion of competence. The layout renders, but as soon as a breakpoint breaks or fine typographic adjustments are required, the learner is completely helpless.

A Bancada de Trabalho Táctil The Tactile Workbench

  • Unidade de trabalho: Linhas de código, seletores individuais, cursor e teclas.Unit of work: Keystrokes, individual selectors, cursor, and files.

3. O Ciclo de Transição em 4 Fases Práticas 3. The 4-Phase Practical Transition Workflow

Fase 01 • Scaffolding Estrutural

Pedir a Estrutura Semântica Sem Estilos Precoces Prompting for Semantic Skeletons Without Premature Styling

Nunca peças: "Cria um site para o meu festival." Pede uma especificação estrutural rigorosa para um componente ou secção. Exige apenas HTML5 semântico com comentários que justifiquem a escolha de cada tag. Never prompt: "Build a festival website." Instead, request a rigorous structural specification for a section. Mandate clean HTML5 with comments explaining why each tag was chosen.

Prompt Modelo: Esqueleto Semântico 
Atua como Arquiteto Web e Mentor de Web Design na FBAUP.
Gera APENAS a estrutura semântica em HTML5 para uma secção de programação musical (lineup) do festival DRUMTIKS '26.

Restrições Obrigatórias:
1. Zero <div>s ornamentais ou desnecessários. Usa exclusivamente marcos (<main>, <section>, <article>, <header>, <time>).
2. Adiciona comentários HTML a justificar por que razão cada tag foi escolhida.
3. Não escrevas CSS nem JavaScript. Eu vou inspecionar o HTML no meu IDE e escrever os meus próprios estilos.
Fase 02 • Inspeção & Diálogo no IDE

Ler Linha a Linha e Questionar o Agente Reading Line-by-Line and Interrogating the Agent

Abre o ficheiro no teu IDE. Percorre as linhas com o cursor. Se encontrares um atributo desconhecido (ex: <time datetime="2026-11-20T22:00"> ou scope="col" numa tabela), interroga o Antigravity ADE antes de avançares: Open the file in your IDE. Step through every line with your cursor. If you encounter an unfamiliar tag or attribute (e.g. <time datetime="..."> or table scope="col"), interrogate Antigravity ADE before moving on:

Prompt Modelo: Interrogação de Linha no IDE 
No ficheiro index.html, linhas 34-38, usaste o elemento <time> com o atributo datetime. 
Explica-me:
1. Qual é o benefício real disto para tecnologias de apoio (leitores de ecrã) e motores de busca?
2. Como é que o browser lida com fusos horários neste formato ISO?
Fase 03 • O Padrão Socratic Sandbox (Projetos Paralelos)

Quando em Dúvida, Criar um Demonstrador Isolado When in Doubt, Spin Up an Isolated Demonstrator

Quando um conceito novo ou snippet complexo surgir (ex: grid-auto-flow: dense, position: sticky que não cola, ou fontes variáveis com font-variation-settings), NÃO tentes adivinhar no teu projeto capstone. Pede ao Antigravity ADE para criar um mini-projeto independente na pasta demos/ com links oficiais da MDN e 3 experiências para o browser: When a complex snippet appears (e.g. grid-auto-flow: dense, a failing position: sticky, or clamp() equations), do not experiment blindly in your capstone project. Prompt Antigravity ADE to spin up an isolated demo in the demos/ folder with official MDN links and 3 browser experiments:

Prompt Modelo: Criação de Socratic Sandbox 
Antigravity, tenho dúvidas sobre como funciona 'position: sticky' quando o elemento-pai tem 'overflow: hidden'.
Cria um projeto de aprendizagem isolado na pasta 'demos/sandbox-sticky/' com:
1. 'index.html': Página minimalista que demonstra lado a lado o caso com erro e o caso resolvido.
2. 'styles.css': Estilos com contornos visuais coloridos para revelar o scroll e a caixa de contenção.
3. Links canónicos para as páginas oficiais da MDN sobre 'position' e 'overflow'.
4. Três desafios práticos em comentário para eu testar diretamente nas DevTools do browser.
Fase 04 • O Laboratório Empírico das DevTools

O Código é Teoria; As DevTools são a Verdade Code is Theory; Browser DevTools are the Truth

O teu ambiente primário de validação visual não é o editor de texto, é a consola de inspeção do navegador. Pede ao agente para guiar a tua inspeção empírica: Your primary validation environment is not your code editor; it is the browser inspection tools. Prompt your agent to direct your empirical debugging:

Prompt Modelo: Diagnóstico Empírico nas DevTools 
O meu layout móvel está a criar uma barra de scroll horizontal indesejada em ecrãs com menos de 480px.
Não me dês a solução de código imediatamente.
Guia-me passo a passo nas DevTools do Chrome/Firefox:
1. Qual separador devo abrir?
2. Que script de consola de uma linha posso correr para encontrar o elemento que excede 100vw?
3. Como utilizo a insígnia 'grid' ou 'flex' para ver onde a grelha colapsou?

5. Biblioteca de Prompts de Tutoria para Alunos 5. Student Mentorship Prompt Library

Guarda estes cinco arquétipos de prompt no teu ficheiro de regras do Antigravity (.gemini/antigravity/rules/) ou nas instruções do teu projeto para moldar o comportamento do agente: Save these five prompt archetypes into your Antigravity project rules or chat to anchor your agent's behavior:

Arquétipo 1: O Mentor Socrático (Explicação de Conceitos) 
Atua como o meu Mentor de Web Design na FBAUP. 
Estou a estudar [INSERE O CONCEITO, ex: a função CSS clamp() para tipografia fluida].
NÃO escrevas o código do meu projeto por mim.
Em vez disso:
1. Explica o modelo mental com uma metáfora visual ligada ao design.
2. Fornece um exemplo mínimo de 8 linhas de código funcional barebones.
3. Dá-me o link direto para a documentação canónica da MDN.
4. Faz-me duas perguntas de diagnóstico para verificar se compreendi verdadeiramente.
Arquétipo 2: O Revisor de Código & Arquiteto de Design 
Atua como Designer Tecnologista Sénior e Revisor de Código. 
Inspeciona o meu ficheiro [CAMINHO, ex: css/styles.css] e [index.html].
Avalia a qualidade do meu trabalho segundo estes três critérios estritos:
1. Pureza semântica: Tenho divs desnecessários ou classes que duplicam seletores nativos?
2. A Regra de Ouro do Layout: Estou a usar CSS Grid para a estrutura 2D e Flexbox para micro-alinhamentos 1D?
3. Design Tokens: Estou a usar variáveis CSS consistentes para espaçamento, tipografia e cor?
Indica apenas as 3 correções mais urgentes e explica a razão técnica de cada uma.
Arquétipo 3: O Auditor de Pré-Publicação (Strict QA) 
Assume o papel de Líder de Controlo de Qualidade Web (QA). 
Inspeciona todos os ficheiros da pasta [CAMINHO DO PROJETO] antes da publicação:
1. Verifica se todos os nomes de ficheiros seguem o padrão minúsculo kebab-case sem acentos nem espaços.
2. Inspeciona todos os links em <link>, <script>, <img> e <a> para garantir que são estritamente relativos.
3. Verifica se as fontes locais WOFF2 têm 'font-display: swap' e se as imagens têm dimensões explícitas para evitar CLS.
Devolve um relatório com a classificação: APROVADO, AVISO ou DEFEITO CRÍTICO, com as instruções de correção.

6. Laboratório Comparativo: Oráculo Ingénuo vs. Mentor Socrático ADE 6. Comparative Lab: Naive Oracle vs. Socratic ADE Mentor

Compara o impacto na aprendizagem entre recorrer a um modelo como "gerador de código pronto" versus utilizá-lo como "mentor e laboratório socrático": Compare the learning outcome between using an AI as a "code generator" versus a "Socratic mentor & sandboxing lab":

O Pedido do Estudante:

"Faz-me uma grelha para os artistas do festival Drumtiks."

O que a IA vulgar responde: Gera 150 linhas de HTML genérico repleto de classes class="col-md-4 card-wrapper", CSS estático e talvez até dependências externas.

O Resultado Pedagógico:
  • O estudante não aprendeu a sintaxe de grid-template-columns nem minmax().
  • Quando o professor pedir para adicionar um vazio editorial (void) ou alterar um breakpoint, o estudante fica paralisado.
  • Zero retenção na memória de longo prazo; perda de controlo do projeto.
O Pedido do Estudante no Modo Antigravity ADE:

"Cria uma sandbox isolada em 'demos/sandbox-grid/' com 6 cartões para eu testar 'minmax(240px, 1fr)' e dá-me o link MDN para 'grid-template-columns'."

O que o Antigravity ADE responde: Cria a pasta, instala um ficheiro index.html minimalista com 6 caixas coloridas, adiciona links diretos para a documentação e sugere que o estudante abra as DevTools para ver o recálculo das pistas em tempo real.

O Resultado Pedagógico:
  • O estudante compreende exatamente o que a unidade fracionária 1fr faz em conjunto com minmax().
  • O projeto capstone principal permanece imaculado e sob o controlo total do autor.
  • Construção de competências de engenharia visual transferíveis e duradouras.
