Stage 00 • Architectural Overview

How Every Deliverable Feeds the Next

Caddick & Cable Intro Fig. 9 • Goodwin Ch. 12–24 • Garrett 5 Planes

UX documentation is never bureaucratic filler (trabalho para encher dossier). As Caddick and Cable demonstrate in Communicating the User Experience, each artifact answers one specific design question and directly generates the inputs for the next artifact—preventing expensive layout rewrites once you start coding semantic HTML5 and responsive CSS.

Stage 01 • Scope & Data Objects

1. Content Inventory & Qualitative Content Audit

Caddick & Cable Ch. 4 • Goodwin Ch. 12 & 16 • Kissane (2011)

Start by cataloging every piece of text, photography, vector diagram, audio sample, downloadable file, and structured table your site needs. Kim Goodwin calls these core nouns Data Objects (Designing for the Digital Age, Ch. 16): before designing a festival artist page, you must know what attributes an Artist object actually carries (stage name, set time, modular gear list, portrait aspect ratio, audio preview). Caddick and Cable (Communicating the User Experience, Ch. 4) pair this quantitative spreadsheet with a qualitative audit so you know whether each item is ready, needs editing, or must still be produced.

✓ Essential Columns for WD101 Inventories

  • Asset ID: Hierarchical code (C-01.1, C-02.1) matching your future Outline and Wireframe callouts.
  • Target File: Destination HTML document (e.g., index.html, dj-warp.html, battle-rules.html).
  • Content Title & Type: Headline copy, editorial body (~250 words), 4:5 portrait WebP, HTML data table, SVG map, etc.
  • Source, Author & AI / License Provenance: Original photography, public domain specimen, CC-BY credit, or explicit AI generation disclosure (mandatory for your credits.html imprint).
  • Action Status: ✓ Ready, ▲ Revise, or ◆ Create.

✕ Common First-Time Student Pitfalls

  • Inventing containers before auditing copy: Designing three equal cards in Figma when one item has 18 words and another has 190 words.
  • Ignoring media aspect ratios: Mixing landscape 16:9 stage photos and vertical 3:4 posters without planning aspect-ratio reservations (causing Cumulative Layout Shift).
  • Forgetting tabular & utility content: Omitting ticket pricing matrices, hardware comparison tables, venue transit instructions, or academic credits until the night before submission.

Stage 02 • Textual Information Architecture

2. Site Outline (Hierarchical Page Specification)

Caddick & Cable Ch. 5 ("Outline View") • WD101 Final Project Brief

Before drawing boxes in a diagramming tool, translate your Content Inventory into a clean, indented Site Outline (Caddick & Cable, Ch. 5). The Outline lets your team and instructor verify page scope, URL naming conventions (lowercase ASCII, hyphen-separated, zero spaces or accents), and template reuse in seconds.

Mandatory WD101 Outline Entry Syntax (Strict Field Order): Every entry in your Site Outline must follow this exact three-part sequence: 1st Page Name → 2nd File Name (*.html) → 3rd Brief Description (summarizing core content, user purpose, and assigned layout template).
— Note how Stage 03 (Swimlane Site Map) intentionally flips #1 and #2 so filename.html leads each visual node.

Stage 03 • Structural Information Architecture

3. Swimlane Site Map (Hierarchical Navigation Destinations Only)

Caddick & Cable Ch. 5 • Garrett Visual Vocabulary • WD101 Strict Spec

A Site Map visualizes the structural hierarchy of discrete pages (or distinct URL-addressable navigation states) across horizontal hierarchical swimlanes. As Caddick and Cable (Communicating the User Experience, Ch. 5) emphasize, first-time designers frequently confuse a Site Map with a flowchart (fluxograma): they draw boxes for "Navigation Bar", "Dropdown Menu", "Click Ticket Button?", or "Yes/No" diamonds. Never do that in a Site Map. Those belong in Stage 04 (User Journey / Flow Diagram).

✓ Mandatory Swimlane Site Map Rules

  • Swimlanes = Navigation Depth Tiers: Organize horizontal bands strictly by structural hierarchy (e.g., Lane 0: Root Landing → Lane 1: Primary Navigation Pages → Lane 2: Category / Detail Pages → Global Utility Lane).
  • Nodes = Pages / Navigation Destinations ONLY: Every box represents a real HTML document or standalone screen state that a user can land on.
  • Garrett Page Stack for Repeated Templates: When multiple items share the exact same HTML/CSS template (e.g., 8 artist profiles modeled on dj-warp.html), draw a stacked card box rather than 8 redundant rectangles.
  • Strict Internal Node Hierarchy (4 Fields): Notice how #1 and #2 invert the Outline order so developers spot the file slug immediately!

✕ What NEVER Appears in a Site Map

  • NO Menus or UI Chrome Boxes: Do not draw a box labeled "Header Menu", "Hamburger Drawer", "Footer Bar", or "Filter Dropdown".
  • NO Flowchart / Decision Diamonds (Não é um fluxograma): Do not draw "User selects VIP?" or Yes/No branching arrows.
  • NO Intra-Page Micro-Interactions: Toggling dark mode, opening a <details> accordion, or clicking a pricing radio button inside index.html stays inside that single page—it is not a separate Site Map destination.
Stage 04 • Behavioral Modeling & Evaluation Bridge

4. Task Model & Expected User Journey / Flow Diagram

Caddick & Cable Ch. 2 & Ch. 3 • Goodwin Ch. 16 & Ch. 23

While the Swimlane Site Map shows static geography (where pages live), a Task Model and Expected User Journey / Flow Diagram show human movement over time: how a visitor arrives with a specific question, evaluates information across pages, makes decisions, and reaches completion.

1. Direct Connection

The user knows exactly what they want and goes straight to it with zero comparison (e.g., "Check what time DJ Warp plays on Saturday night"). Design requirement: clear scent of information and zero unnecessary clicks.

2. Controlled Evaluation

The user compares 2–3 bounded options against clear criteria before acting (e.g., "Compare a Day Pass vs. Full 3-Day Pass + Masterclass bundle within a €75 student budget"). Design requirement: transparent side-by-side pricing feedback.

3. Complex Evaluation

The user loops across multiple sources and constraints before committing (e.g., "Verify whether my Roland SP-404MKII + external laptop setup qualifies for The 808 Clash before registering"). Design requirement: scannable rules + hardware table + clear recovery paths.

Downstream Reuse A — Formative Heuristic Evaluation & Walkthrough

Before showing your prototype to anyone else, walk step-by-step through your Expected User Journey alongside the Interactive Heuristic Evaluation Checklist and Heuristics Guide (Goodwin, Ch. 23):

  • At every page transition, check Williges/Cognitive Walkthrough questions: Is the link visible? Does its label match the user's goal words, not internal jargon?
  • At every decision point, verify Nielsen #6 (Recognition rather than recall): does the user have to memorize prices from one screen to compare them on another?
  • At every loopback, verify Nielsen #3 (User control and freedom): can the user return without losing context?

Downstream Reuse B — Quick & Dirty Peer Usability Sessions

Do not invent random usability tasks at the end of the semester! As Goodwin (Ch. 23) and Rubin & Chisnell (Ch. 5) explain, each Expected User Journey converts directly into one Usability Test Task Scenario in Stage 06:

  • Journey Trigger → becomes your Task Scenario Prompt read aloud to your friend/colleague.
  • Expected Path → becomes your Optimal Click Benchmark (e.g., 2 page loads).
  • Journey Outcome → becomes your objective Successful Completion Criterion (SCC).
Stage 05 • Screen Skeleton & Interactive Prototyping

5. Designing Lower- or Higher-Fidelity Wireframes in Figma

Caddick & Cable Ch. 6 • Goodwin Ch. 14, 16, 23, 24 • Cooper Ch. 5 • Stage 1 Figma Spec (Weeks 5-8)

Wireframes bridge abstract architecture and visual HTML/CSS code. Whether you choose Lower-Fidelity Grayscale Wireframes or Higher-Fidelity Interactive Prototypes in Figma (or Penpot), Kim Goodwin (Designing for the Digital Age, Ch. 14 & Ch. 23) warns of a classic student trap: fidelity dictates the feedback you get. Rough, uncolored layouts invite honest critique about hierarchy and missing content; polished dark-mode neon UI makes friends comment on colors and fonts while overlooking broken navigation.

Stage 06 • Empirical Validation with Friends & Colleagues

6. Usability Test Protocol & Actionable Report (First-Timer Guide)

Rubin, Chisnell & Spool (2008) • Krug Ch. 9 • Caddick & Cable Ch. 7–8

As Jared Spool notes in the foreword to Handbook of Usability Testing (Rubin & Chisnell, 2008), design teams rarely make bad decisions on purpose—they make bad decisions because key information about real user behavior was missing when they argued about layouts. Even if you have never moderated a usability test before, watching just 3 to 5 friends or FBAUP colleagues (who did not work on your project) attempt 3 realistic tasks for 15–20 minutes will expose ~80% of your site's most damaging navigation, copy, and layout barriers.

Golden Rule for First-Time Moderators (Rubin & Chisnell Ch. 1 & Ch. 9; Krug Ch. 9): A usability test is not a focus group (never test peers in a group asking "Do you like this color?") and not a guided demo. Test one person at a time, give them a concrete goal without using your menu words, ask them to think out loud, and hold your tongue when they hesitate—that silence is where you learn what your design failed to communicate.
— Synthesized from Handbook of Usability Testing (2nd ed., Ch. 5, 8, 9) & Don't Make Me Think, Revisited (Ch. 9: "Recruit loosely and grade on a curve").

1. Sample & Device Split

  • 4–5 Participants Total: Friends, roommates, or students from other studios/years (`P1`–`P5`, anonymized in your report).
  • Test Both Postures: Run at least 2 sessions on a real smartphone (`375–412px`) and 2–3 sessions on a laptop/desktop.
  • Counterbalance Task Order: Give `P1`/`P3` Tasks `1 → 2 → 3` and `P2`/`P4` Tasks `2 → 3 → 1` so learning effects don't skew Task 3 (Rubin Ch. 5).

2. Seating & Roles (15–20 Min)

  • Moderator: Sits slightly behind and ~45° to the side so you see both screen and finger/mouse without intimidating the participant (Rubin Ch. 9).
  • Note-Taker (Observer): Logs clicks, hesitations, quotes, and shorthand codes silently—never interrupts!
  • Timeline: 2 min orientation → 3 min Home Page Tour → 10 min for 3 tasks → 3 min debrief & ratings.

3. Top Things NEVER to Say

  • ✕ "Click on '808 Clash' in the top right..." (Leading / giving away the UI label!)
  • ✕ "Actually, we put that table there because..." (Defending your design!)
  • ✕ "Isn't this pricing calculator super clear?" (Biased yes/no prompt!)
  • ✓ Say instead: "What are you thinking right now?" or "What did you expect would happen?"

How to Log Observation & Efficiency (Keep It Simple!)

  • 1. Task Completion Rate (Effectiveness): Score each task objectively: 100% = Completed independently; 50% = Completed only after a moderator hint; 0% = Gave up or stated wrong answer without noticing (false completion—watch closely for this!).
  • 2. Clicks & Hesitations vs. Stopwatch Time (Efficiency): Count actual page loads vs. your Optimal Path (e.g., 5 clicks vs. 2 optimal) and count pauses >5 seconds. Rubin & Chisnell Caveat (Ch. 5): Because asking peers to Think Aloud naturally slows down reading, never panic over raw seconds alone—use Median time alongside click detours so one chatty friend doesn't skew your average!
  • 3. Post-Task Single Ease Question (SEQ): Right after each task, ask: "Overall, how difficult or easy was that task, from 1 (Very Difficult) to 7 (Very Easy)?" Anything averaging below 5.0 needs redesign.

Caddick Note Codes & Rubin Criticality Score

  • Rapid Note-Taking Symbols (Caddick & Cable Fig. 7-10): " Verbatim quote • ! Critical barrier/error • * Hesitation or layout insight • ? Participant confusion • + Positive reaction • ?? Probe during debrief (Rubin Ch. 10).
  • Rubin's Prioritization Formula (Ch. 11): Rank every observed problem using Criticality = Severity (1–4) + Frequency (1–4):
    • Severity: 4 Unusable/Blocks task • 3 Severe friction • 2 Moderate detour • 1 Minor cosmetic annoyance.
    • Frequency: 4 ≥4 of 5 peers • 3 3 of 5 peers • 2 2 of 5 peers • 1 1 of 5 peers.
    • Action Threshold: Scores 7–8 = Mandatory immediate fix; 5–6 = High-priority fix; 2–4 = Polish if time permits.
