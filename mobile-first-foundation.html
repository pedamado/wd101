1. A Filosofia Pedagógica Holística da WD101 1. The Holistic Pedagogical Philosophy of WD101

A abordagem nestas primeiras semanas é holística, iterativa e faseada em níveis. Não aprendemos propriedades CSS isoladas em abstrato; cada elemento HTML e linha de CSS responde diretamente à forma como o navegador desenha píxeis no ecrã e como os dados circulam fisicamente na rede mundial de computadores. Our pedagogical approach in these initial weeks is holistic, iterative, and staged by tiers. We do not memorize CSS properties in a vacuum; each HTML element and line of CSS directly responds to how the browser paints pixels on screen and how data physically travels across the global computer network.

O Princípio da Simplicidade Estrutural (Semanas 1 e 2) The Principle of Structural Simplicity (Weeks 1 and 2)

Apenas 1 página HTML (index.html) + 1 ficheiro CSS (css/style.css). Sem imagens externas, sem ficheiros multimédia adicionais e com zero JavaScript. O foco absoluto é dominar a árvore semântica do HTML5, o fluxo normal do documento, as 3 tipologias de hiperligações e o modelo de caixa básico.

Exactly 1 HTML file (index.html) + 1 CSS file (css/style.css). Zero external images, zero extra media, and zero JavaScript. The absolute pedagogical priority is mastering HTML5 semantic DOM trees, document normal flow, the 3 hyperlink typologies, and box model foundations.

3. A Regra de Ouro Obrigatória (Semanas 1 e 2) 3. The Mandatory Golden Rule (Weeks 1 and 2)

Para incutir uma compreensão visceral da hierarquia e herança em cascata (relação entre elementos pais, irmãos e filhos), nesta UC é rigorosamente obrigatório durante as primeiras duas semanas declarar explicitamente em todos os contentores estruturais: To instill an instinctive grasp of document hierarchy and cascading inheritance (parent, sibling, and child relationships), in this course it is strictly mandatory during weeks 1 and 2 to explicitly declare on all structural landmark containers:

1. position: relative;

Garante que o elemento permanece dentro do fluxo normal do documento, mas estabelece o contexto de posicionamento para o seu espaço geométrico. Keeps the element in normal document flow while defining a local coordinate context for its geometrical space.

2. display: block;

Ocupa a largura total da linha e empilha os irmãos verticalmente. Força a disciplina do modelo de caixa antes de usar Flexbox ou Grid. Occupies full line width and stacks siblings vertically. Enforces box model discipline before introducing Flexbox or Grid.

3. Dimensões RelativasRelative Dimensions

O body referencia o viewport (100vw / 100vh), e todos os elementos descendentes usam medidas relativas (percentagens e rem), herdando o espaço dos pais. The body references the viewport (100vw / 100vh), and all descendant elements use relative measures (% and rem).

4. Limites ElásticosElastic Boundaries (min / max)

Mobile-First desde o 1.º dia: min-width: 320px; (garantia para ecrãs pequenos) e max-width: 75ch; (limite tipográfico ergonómico de leitura). Mobile-First from day one: min-width: 320px; (small screen guarantee) and max-width: 75ch; (ergonomic reading line length limit).

4. Anatomia do Documento HTML5 & Landmarks 4. HTML5 Document Anatomy & Landmarks

Estrutura semântica rigorosa com identificadores para criação de Named Anchors (ligações internas): Strict semantic structure with IDs configured for internal Named Anchors:

  • <!DOCTYPE html> & <html lang="pt">: Declaração padrão e raiz com metadados de idioma.Standard declaration and root element with language metadata.
  • <head>: Contém o <title> e a ligação à folha de estilos <link rel="stylesheet" href="css/style.css">.Houses <title> and stylesheet reference <link rel="stylesheet" href="css/style.css">.
  • <body>: Corpo principal do documento (tamanho relativo ao viewport).Main document body (sized relative to viewport).
  • <header>: Cabeçalho com <h1> principal e navegação <nav> com lista de links <ul> <li> <a>.Header with primary <h1> and navigation <nav> containing link list <ul> <li> <a>.
  • <main>: Conteúdo principal estruturado em <section> (cada uma com <h2>) e <article> (com <h3> e <p>).Main content structured into <section> (each with <h2>) and <article> (with <h3> and <p>).
  • <aside>: Conteúdo complementar lateral, exemplificado com Lista de Definições (<dl>, <dt>, <dd>).Complementary content, exemplified via a Description List (<dl>, <dt>, <dd>).
  • <footer>: Rodapé do documento com créditos, direitos de autor e link de retorno ao topo.Document footer containing copyright notice and return-to-top anchor.

5. O Inspetor do Browser: O Teu Melhor Amigo 5. The Browser Inspector: Your Best Ally

Sempre que algo não se comporta como esperado no ecrã, não adivinhe: inspecione visualmente. Whenever something misbehaves on screen, do not guess: inspect visually.

  • Como abrir: Botão direito do rato sobre qualquer elemento → Inspecionar (ou Cmd + Option + I no Mac / F12 no Windows).How to open: Right click any element → Inspect (or Cmd + Option + I on Mac / F12 on Windows).
  • Modo de Dispositivos Móveis: Clique no ícone de telemóvel/tablet para testar larguras reais de 320px, 375px e 414px.Responsive Device Mode: Tap the phone/tablet icon to test actual widths at 320px, 375px, and 414px.
  • Edição em Tempo Real: Pode ativar/desativar regras CSS e testar valores no painel Styles sem ter de guardar o ficheiro.Live Editing: Toggle CSS declarations and tweak property values in the Styles panel in real-time.
  • Visualizador do Modelo de Caixa: Observe as cores que o browser desenha para Content (azul), Padding (verde), Border (amarelo) e Margin (laranja).Box Model Visualizer: Inspect browser color highlights for Content (blue), Padding (green), Border (yellow), and Margin (orange).

6. Publicação por sFTP no pages.up.pt & Nomenclatura 6. Publishing via sFTP to pages.up.pt & Naming Rules

Testar no disco rígido local (file:///) não é suficiente. O trabalho de web design só está concluído quando é servido através de um protocolo HTTP/HTTPS num servidor real. Testing locally from a hard drive (file:///) is not sufficient. Web design work is only verified once served through HTTP/HTTPS from a live production server.

Regras Rígidas de Nomenclatura de Ficheiros (URLs Universais) Strict File Naming Rules (Universal URLs)

  • Apenas minúsculas: Os servidores Linux diferenciam maiúsculas de minúsculas (Index.html vs index.html). Use sempre minúsculas.Strictly lowercase: Linux servers are case-sensitive (Index.html vs index.html). Always use lowercase.
  • Sem espaços: Substitua espaços por hífen (meu-exercicio-1 e nunca meu exercicio 1).No spaces: Replace spaces with hyphens (my-assignment-1, never my assignment 1).
  • Sem acentos ou cedilhas: Evite caracteres como ã, é, ç nos nomes de pastas e ficheiros para evitar erros de codificação de URL (ex: %20 ou %C3%A7).No accents or special characters: Avoid accented characters in file names to prevent percent-encoding errors.
  • O ficheiro de entrada: Tem de chamar-se obrigatoriamente index.html para que o servidor o sirva automaticamente como raiz da pasta.Entry point file: Must be named index.html so web servers serve it automatically as directory index.

Dados de Ligação sFTP (pages.up.pt) sFTP Connection Details (pages.up.pt)

  • Protocolo: SFTP (SSH File Transfer Protocol)
  • Servidor / Host: sigarra.up.pt ou pages.up.pt
  • Porta: 22
  • Utilizador: O teu número de estudante (ex: up202612345)
  • Palavra-passe: A senha institucional da Universidade do Porto
  • Pasta Remota: Publicar dentro de public_html/Remote Directory: Upload inside public_html/
